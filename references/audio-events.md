# 音频事件候选与人工校正

在为图片切换寻找音乐落点、解释 `events.json`，或选择音乐片段时读本文件。运行参数以 `scripts/analyze_audio.py --help` 为准。

## 方法的证据边界

这套算法从本地钢琴短片工程提取：512/1024 样本双窗正对数频谱通量，减去局部中位基线，再在频谱候选附近寻找波形能量的正上升沿。22050Hz 解码，110 样本步长约 4.99ms。它采用起音附近的波形上升沿坐标，避免把宽窗回溯点当作已证实的起音；这是信号与波形检查层面的验证，尚不能代替人工听音。

原工程曾按特定时间人工排除两个疑似混响变化。本脚本已去掉曲目时间特例及旧报告依赖，因此不能假设可复现原工程人工修订后的数量。低置信点全部留在输出里。

2026-10-25 用原工程的 17.5 秒钢琴 WAV 做机械回归：57 个候选时间与旧报告全部一致，最大时间差为 0；本版 52 个暂接纳、5 个 low，旧版排除曲目特例后为 50 个暂接纳。另测 2..5 秒选段，确认时间仍落在输入文件的 2..5 秒内。生成并目视检查波形/novelty 图、验证点击与解码 WAV 长度；未人工听证，也未验证混合 BGM 分类能力。

混合 BGM 的鼓、人声、其他乐器、压缩和混响都会引起频谱变化。此方法提供 **onset 候选**；未实现声部分离、歌词识别、钢琴/鼓分类、重拍识别或音乐小节识别。`--event-type piano_attack` 只是调用者已知输入为钢琴时记录的假设，脚本不会验证该假设。

## 运行与检查

依赖 Python、numpy、scipy、imageio-ffmpeg；`--plot` 另需 matplotlib。脚本内设置 `sys.dont_write_bytecode=True`，导入本脚本前也应设置它，以免在 skill 目录生成缓存。

```powershell
py -3.11 <skill>/scripts/analyze_audio.py --audio <本地音频> --output-dir <全新分析目录> --start 12 --duration 18 --plot --click-track
```

默认只生成 `events.json`。`--plot` 生成波形和 novelty 曲线，绿色为自动暂接纳点，琥珀色为低置信点；`--click-track` 生成所选片段的点击监听 WAV，暂接纳点 1800Hz，低置信点 900Hz；`--write-wav` 输出未经点击混音的解码片段。输出 WAV 从片段起点播放，监听中的本地时间需加 `analysisOffset` 才与 JSON 对齐。检查音轨仅供校对，不能误当成正式配乐。

默认 `min-gap=.11` 秒、`height=.055`、`prominence=.045`。调低阈值会增加弱起音，也更容易带入尾音变化。`min-gap` 会抑制距离更近的检测点，不能把未检出的更快演奏直接认定为不存在。一次选段默认最多 120 秒，超出时报错而非静默截断；先按用户给的素材范围使用 `--start/--duration`。确有必要时显式提高 `--max-analysis-seconds`，内存随时长增加。

已有输出会拒绝覆盖，保留人工编辑。改参数时换新输出目录并比较，不要拿重新检测结果覆盖已校对文件。

## 时间与 JSON 合约

`schemaVersion=1`，`sourceAudio` 为输入音频的绝对路径，`durationSeconds` 为整个输入文件时长（非 WAV 容器元数据时长可能有精度误差）。`analysisOffset` 是选段起点；`analysisDurationSeconds` 是实际解码长度。

**每个 `events[].timeSeconds` 已包含 `analysisOffset`，始终相对本次输入音频文件开头。** 若输入本身是从歌曲裁出的 WAV，零点就是该 WAV 开头；不能自动推回歌曲原始时间。需要原歌坐标时由调用者另行保留裁剪回执。用于片段视频的时间应为 `event.timeSeconds - videoAudioStartSeconds`，只减一次。

事件必要字段：

```json
{
  "id": "event-0001",
  "timeSeconds": 12.034,
  "strength": 0.42,
  "confidence": "high",
  "type": "onset",
  "accepted": true
}
```

`strength` 在本次分析片段内归一化为 0..1，跨片段不可直接比较。`confidence` 是信号支持的启发式分类，不是概率。high/medium 默认 `accepted=true`，仅表示可供后续编排暂用；low 默认 false 但保留。`humanListeningVerified=false` 和 `humanReviewStatus=unreviewed_candidates` 清楚记录尚未人工听证。`diagnostics` 提供频谱峰、双窗强度和波形上升支持，方便逐点检查。

选段边缘可能截入持续音，末尾 40ms 检测有保护区。听音时检查首尾，必要时扩大输入选段提供上下文再校对；不要把边缘漏检用等距点补齐。

## 从候选到可用切点

1. 听原片段和点击音轨，查看峰值附近波形。删除尾音/混响伪峰，纠正偏移，明确保留的弱起音。
2. 人工可编辑 `accepted`、删除事件或补入实际听见的起音。补点给新唯一 ID；使用同一输入文件时间基准，并另记手工来源。确认完成后更新审核状态及回执，保留未修订分析文件。
3. 只取实际存在且适合画面节奏的事件。起音可以是切分音或细分音，候选密度变化不等于 BPM 加速。没有足够落点时，先调整片段或图片使用计划；禁止按均匀 BPM 网格补点冒充检测结果。

## 片段选择与图片数量

先根据用户给定范围找乐句的自然起点和尾部，再看候选点是否支撑图片数量。图片数量与可用起音点只是编排约束；一张图也可能跨多个起音、多个图也可能分组呈现。需要每图一个真实切点而候选不足时，说明缺口并选择更长或更密的已授权片段，或减少图片；不要复制音乐伪装成不同段落。

结尾应留出最后一张图的可见时长及乐句尾音，避免仅为凑数量把末图压成几帧或在音符衰减中硬截。若尾部需要避开字幕、转场或静帧，编排时明确标注。最终播放视频确认视觉切换与听感，分析成功和文件存在不能代表卡点已人工验收。
